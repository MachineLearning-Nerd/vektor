# Task 1.7 — v0.1.0 release tag + artifacts

**Phase**: 1 — Skeleton
**Task ID**: 1.7
**PRD reference**: VEKTOR_ROADMAP.md Stage 2 brought-forward C8.1 (lite matrix) + L2 (README) + L3 (LICENSE)
**Roadmap stage**: Stage 2 / `v0.1.0` (the release tag itself)
**Effort estimate**: M (1–4h)
**Depends on**: 0.2 (CI), 0.4 (cargo-deny), 1.6 (MCP serve works)
**Blocks**: 2.* (all Phase 2 tasks)

## Objective

Cut the `v0.1.0` release. This task:
1. Verifies all Phase 0 + Phase 1 tasks (0.1–1.6) are ✅ Done
2. Confirms the README, LICENSE, and CI all reflect the v0.1 state accurately
3. Tags `v0.1.0` and pushes the tag
4. Triggers CI to build release artifacts
5. Creates a GitHub Release with downloadable binaries for the lite matrix (macOS-aarch64 + linux-x86_64)
6. Marks Phase 1 complete and **expands Phase 2's per-task files** so Phase 2 can begin

## Inputs (must exist before starting)

- Tasks 0.1, 0.2, 0.3, 0.4, 1.1, 1.2, 1.3, 1.4, 1.5, 1.6 all ✅ Done
- CI is green on `main` (no broken state)
- `README.md` and `LICENSE` exist (already committed in `3d81fa6`) and accurately describe v0.1.0
- All Phase 1 exit criteria from `phase-1-skeleton/README.md` checked

## Outputs (must exist after completion)

- Git tag `v0.1.0` pushed to origin
- GitHub Release `v0.1.0` with attached binaries: `vektor-darwin-aarch64.tar.gz`, `vektor-linux-x86_64.tar.gz` (and their `.sha256` companions)
- `README.md` Status badge / link reflects "v0.1.0 released — skeleton" if any such badge exists
- `VEKTOR_ROADMAP.md` Current State table updated: Stage 2 status changed from "Not started" to "In progress — v0.1.0 shipped, v0.2.0 next"
- `docs/plans/initial/README.md` Current State updated
- **`docs/plans/initial/phase-2-discovery-chunking/` expanded**: phase README augmented with full per-task files (01-…md through 09-…md) so Phase 2 work can start
- Phase 2 dependencies updated in `DEPENDENCIES.md` (set unblocked tasks from 🟡 to 🟢)

## Approach

1. **Pre-flight checks**:
   ```bash
   # Verify CI green on main
   gh run list --branch main --limit 1 --json conclusion -q '.[0].conclusion'   # expect: success

   # Verify all Phase 0/1 tasks done
   grep "⬜" docs/plans/initial/phase-{0,1}*/README.md && echo "FAIL: open tasks" || echo "OK"

   # Verify version in Cargo.toml
   grep '^version = ' Cargo.toml | head -1   # expect: version = "0.1.0"

   # Verify no Co-Author lines in commits since last tag
   git log --format="%H%n%B" --since="last release" | grep -i "co-author" && echo "WARN: Co-author present" || echo "OK"

   # Verify all tests pass
   cargo test --workspace --release
   ```

2. **Update READMEs to reflect "v0.1.0 shipped"**:
   - In `README.md`, change the status badge from `pre--alpha (design)` to `v0.1.0 — skeleton released` and update the "Status" section
   - Update `docs/plans/initial/README.md` Current State row for Phase 1 to ✅ with commit hash range
   - Update `VEKTOR_ROADMAP.md` Current State accordingly

3. **Tag the release**:
   ```bash
   git tag -a v0.1.0 -m "v0.1.0 — Skeleton release

   First runnable Vektor binary. CLI parses, MCP server starts over
   stdio and registers 3 no-op tool handlers. No real indexing,
   embedding, search, or context assembly yet — those land in
   subsequent phases.

   See VEKTOR_ROADMAP.md Stage 2 and docs/plans/initial/ for the
   staged plan."

   git push origin v0.1.0
   ```

4. **Trigger the release build**. Either:
   - Add a `release.yml` GitHub Actions workflow that fires on tag push (preferred — automates future releases), OR
   - Manually run `cargo build --release` on each target platform and upload tarballs via `gh release upload`

   For v0.1.0, the **manual path is acceptable** because the full release pipeline doesn't exist yet (task 6.2). Document the manual steps in the task Notes section so future-you knows what was hand-crafted.

5. **Create the GitHub Release**:
   ```bash
   gh release create v0.1.0 \
     --title "v0.1.0 — Skeleton" \
     --notes-file release-notes-v0.1.0.md \
     vektor-darwin-aarch64.tar.gz \
     vektor-darwin-aarch64.tar.gz.sha256 \
     vektor-linux-x86_64.tar.gz \
     vektor-linux-x86_64.tar.gz.sha256
   ```

6. **Expand Phase 2 task files** — this is the most important post-release step:
   - For each task in `docs/plans/initial/phase-2-discovery-chunking/README.md`'s task list, create the corresponding `NN-task-name.md` file following the template in `AGENTS.md` and the style of Phase 0/1 task files.
   - Cross-reference PRD Section 12 Week 2 (Functions 2.1–2.5) for each task's PRD reference.
   - Update `DEPENDENCIES.md`'s Phase 2 table to mark tasks 🟢 (unblocked) where appropriate (e.g., 2.1 becomes 🟢 the moment 1.7 ships).
   - **Do not start any Phase 2 task before all Phase 2 per-task files exist.** This is the AGENTS.md rule.

7. **Final commit** for the version bumps, README updates, and Phase 2 expansion. Tag this commit as the release commit:
   ```bash
   git add -A
   git commit -m "release: 1.7 — v0.1.0 release + Phase 2 task-file expansion

   ... (full message per AGENTS.md format)"
   git tag -a v0.1.0 ...
   ```

## Notes / open questions

- **Manual release for v0.1.0, automated for v0.4.0**: this task's manual cross-platform build is a one-off acceptable shortcut. Task 6.2 builds the full release pipeline. Document what was done by hand in case future-you needs to reproduce.
- **`gh release` requires gh CLI auth**: run `gh auth status` first; re-auth if needed.
- **Don't squash-merge releases**: tags should point at a specific commit. Squash-merging on GitHub can move the commit out from under the tag.
- **Phase 2 expansion is part of THIS task**: AGENTS.md says don't start Phase N without its per-task files. The release task is the natural place to do that expansion — fresh from shipping v0.1, the work for v0.2 is most clearly understood.
- **README badge accuracy**: a "pre-alpha" badge claiming there's no code is wrong after v0.1.0 ships. The shame is worse than the work — update it.
